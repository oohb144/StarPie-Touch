# 触控版首次安装官方插件

从 `v1.8.0-touch.5` 开始，无需先下载或运行官方 StarPie 主程序来安装插件。

1. 下载本仓库的 **Standalone** ZIP，解压到新目录并运行 `StarPie.exe`。Lightweight 版需要 .NET 8 Desktop Runtime。
2. 打开控制台的「插件」页，点击「刷新目录」。等待状态行显示目录版本和模块数量。
3. 对所需模块点击「下载并安装」。下载、包大小、包 SHA-256、程序集 SHA-256 和插件加载均成功后，模块会在本机登记并启用。
4. 设置相应轮盘动作。已安装模块在断网时仍可使用。

主程序不会在启动时自动下载或安装插件。官方插件来自 [StarPie-Official-Plugins](https://github.com/Star-Pie/StarPie-Official-Plugins/releases)，不随主程序包携带。智识插件仍从触控版 Release 的独立 ContentInsight ZIP 手动安装。

## 已修复的原因

旧触控版只接受 catalog schema 1 的平铺条目。官方最新目录使用 schema 2，每个模块下有一个 `versions` 列表，旧解析器会在显示下载按钮前拒绝整份目录。官方主程序能安装这些插件，而两种主程序默认共用 `%LOCALAPPDATA%\StarPie\plugin-data`，因此先用官方版安装会掩盖下载入口的缺陷。

新解析器兼容两种格式，验证每个版本的资产地址、大小和哈希，再按 SDK、宿主版本与运行框架选择最新兼容版本。官方最新版本需要更高 SDK 时，可以选择目录保留的历史兼容版本；不会把已经安装的更高版本自动降级。

当前触控版保留 SDK 1.5，并回移了新版程序启动插件所需的部分接口。它没有完整实现上游 SDK 1.6–1.8。悬浮球与键盘层等没有兼容版本的模块会显示 SDK 要求，安装按钮不可用；这是明确的兼容边界。

## 验证范围

`scratch/OfficialPluginTests` 使用独立的空 LOCALAPPDATA、插件宿主目录和下载目录，直接调用正式主程序的目录解析、下载与安装代码。验证 schema 1/2、兼容版本选择、无效目录拒绝、禁止降级、真实插件初始化、默认动作类型路由和断网重新加载。测试保留所有沙箱，不修改用户真实配置或已安装插件。

下载依赖本机能够访问 GitHub 及其 Release 资产域名；首次安装不要求 GitHub 账号或 Token。完整 GUI、实机触屏和具体动作的系统副作用仍由人工验收。
